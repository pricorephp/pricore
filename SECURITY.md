# Security Policy

Pricore stores and distributes private source code, and holds credentials for the Git
hosts it syncs from. We take reports seriously and respond quickly.

## Supported Versions

Security fixes are released for the latest minor version. Self-hosted installations
should track the `latest` Docker tag or pin to a major version tag (`v1`).

| Version | Supported |
| ------- | --------- |
| Latest release | Yes |
| Older releases | No — upgrade to the latest |

## Reporting a Vulnerability

**Do not open a public issue.** Report privately by email to **security@pricore.dev**,
or through [GitHub's private vulnerability reporting](https://github.com/pricorephp/pricore/security/advisories/new).

Please include, where you can:

- What the issue is and why it matters
- Steps to reproduce, or a proof of concept
- The version or commit you tested
- Whether it is already public anywhere

You will get an acknowledgement within 3 working days and an assessment within 10.
We will keep you updated as we work on a fix, credit you in the advisory unless you
prefer otherwise, and let you know before we publish.

Please give us a reasonable window to ship a fix before disclosing publicly.

## Scope

In scope: authentication and token handling, cross-organization data access, the
Composer API, webhook verification, repository and mirror syncing, and the published
Docker image.

Out of scope: findings that require an already-compromised host or database, missing
hardening headers with no demonstrated impact, and reports generated by automated
scanners without a working proof of concept.

## Deployment Notes

A few settings materially affect the security of a self-hosted install:

- **`APP_KEY`** encrypts stored Git credentials and SSH private keys. Back it up — losing
  it makes those credentials unrecoverable — and never share it between environments.
- **`SIGN_UP_ENABLED`** defaults to `false`. Leaving it on means anyone who can reach the
  instance can register and create an organization.
- **`OUTBOUND_ALLOWED_HOSTS`** opts hosts back in past the private-range block that
  protects repository and mirror fetches. Only add hosts you control.
- **`TRUSTED_PROXIES`** must be set when running behind a reverse proxy, or Pricore will
  generate `http://` URLs and log the proxy's address instead of the client's.
